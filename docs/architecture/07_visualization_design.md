# Visualization Design

## 1. Overview

The visualization layer represents the final stage of the Lakehouse architecture, providing users with direct access to curated analytical datasets.

Apache Superset has been selected as the Business Intelligence platform due to its Open Source nature, web-based interface, and integration capabilities with SQL query engines such as Trino.

The visualization layer enables users to explore meteorological and energy data through interactive dashboards, charts, filters, and analytical reports without requiring direct access to the underlying Lakehouse infrastructure.

Only datasets published in the Gold layer are exposed for analytical consumption, ensuring that all visualizations are based on validated, standardized, and business-ready data.

## 2. Business Intelligence Architecture

The Business Intelligence layer provides analytical access to the curated datasets generated by the Lakehouse.

Apache Superset connects to Trino to execute analytical SQL queries against the Gold layer. Trino provides the dedicated query layer over the Apache Iceberg tables stored in MinIO, preventing the visualization platform from depending directly on the Spark processing engine.

The Business Intelligence architecture follows a clear separation of responsibilities:

- Apache Spark and Spark SQL prepare and transform the analytical datasets.
- Apache Iceberg provides the Lakehouse table format.
- MinIO provides the underlying object storage.
- Trino provides the distributed SQL query interface.
- Apache Superset delivers data visualization and interactive analysis.

The resulting analytical flow is:

```text
Gold Layer
    │
    ▼
Apache Iceberg
    │
    ▼
   Trino
    │
    ▼
Apache Superset
    │
    ▼
Dashboards / KPIs / Analysis
```

This separation simplifies maintenance, improves data consistency, and decouples interactive analytical workloads from the data processing layer.

## 3. Dashboard Strategy

The visualization layer is designed to provide a set of dashboards that support the exploration and analysis of meteorological and energy data.

Rather than presenting raw datasets, dashboards expose curated information through interactive visualizations that enable users to identify trends, compare regions, and explore relationships between different variables.

The dashboards are organized according to the main analytical domains of the project:

- **Meteorological Dashboard**

  Focused on weather variables such as temperature, precipitation, wind speed, and other available meteorological indicators.

- **Energy Dashboard**

  Focused on electricity generation, energy demand, and electricity market prices.

- **Integrated Analysis Dashboard**

  Combines meteorological and energy datasets to explore potential relationships between weather conditions and the behaviour of the electrical system.

Each dashboard provides interactive filtering capabilities and supports exploratory analysis without requiring knowledge of the underlying data model or Lakehouse infrastructure.

## 4. Key Performance Indicators

The visualization layer provides a collection of Key Performance Indicators (KPIs) that summarize the most relevant meteorological and energy information available in the Lakehouse.

KPIs are calculated from the curated datasets stored in the Gold layer and provide a concise overview of the system without requiring users to explore the underlying datasets.

The platform is designed to support indicators related to:

- Meteorological conditions.
- Electricity generation.
- Electricity demand.
- Electricity market prices.
- Temporal evolution of the analyzed variables.
- Comparative analysis between Autonomous Communities.
- Relationships between meteorological conditions and energy variables.

The final set of KPIs will be defined during the implementation of the Gold analytical layer according to the data effectively available from the selected public APIs.

## 5. Data Exploration

The visualization layer supports interactive data exploration, allowing users to analyze curated datasets from multiple perspectives without requiring direct access to the underlying data model.

Apache Superset provides a flexible environment where users can filter, compare, and explore meteorological and energy data through interactive visualizations and analytical dashboards.

Analytical queries generated by Superset are executed through Trino, which accesses the corresponding Apache Iceberg tables in the Gold layer.

The platform supports exploratory analysis by enabling users to:

- Filter data by time period.
- Compare different Autonomous Communities.
- Analyze historical trends.
- Explore relationships between meteorological and energy variables.
- Navigate through different levels of analytical detail.
- Compare the evolution of multiple indicators over time.

This interactive approach allows users to identify patterns, trends, and correlations while maintaining a simple and intuitive user experience.

## 6. Gold Layer Consumption

The visualization layer consumes exclusively curated datasets from the Gold layer.

This design prevents Apache Superset from accessing raw Bronze datasets or intermediate Silver datasets and establishes a clear contract between the Data Engineering and Business Intelligence layers.

The analytical access path is:

```text
Bronze
   │
   ▼
Silver
   │
   ▼
 Gold
   │
   ▼
 Trino
   │
   ▼
Superset
```

Gold datasets are designed specifically for analytical consumption and may include:

- Aggregated meteorological indicators.
- Energy demand metrics.
- Electricity generation metrics.
- Electricity price indicators.
- Regional comparisons.
- Time-based aggregations.
- Integrated meteorological and energy indicators.

This approach reduces transformation logic inside the visualization layer and ensures that business calculations remain centralized within the Data Engineering pipeline.

## 7. Role of Trino in the Visualization Layer

Trino acts as the SQL access layer between Apache Superset and the Lakehouse.

The introduction of Trino provides a clear separation between processing and analytical querying:

```text
Processing                         Analytics

Spark / Spark SQL                 Apache Superset
       │                                │
       ▼                                ▼
 Apache Iceberg  ◄──────────────────  Trino
       │
       ▼
     MinIO
```

Apache Spark is optimized for distributed processing and transformation workloads, while Trino provides an SQL-oriented interface suitable for interactive analytical queries.

This architecture allows Apache Superset to query the Gold datasets without requiring direct interaction with the Spark cluster.

The use of a dedicated query engine also improves the modularity of the platform, since additional SQL-based analytical consumers could access the same Lakehouse datasets through Trino in the future.

## 8. Design Principles

The visualization layer has been designed according to the following principles:

- **Business-ready data**

  All dashboards and visualizations are based exclusively on curated datasets from the Gold layer.

- **Consistency**

  All reports use the same analytical datasets, ensuring that users work with consistent and validated information.

- **Interactivity**

  Dashboards support filtering and exploration, allowing users to analyze the data from different perspectives.

- **Usability**

  Visualizations are designed to present complex analytical information in a clear, intuitive, and accessible manner.

- **Scalability**

  New dashboards, KPIs, and analytical views can be added without modifying the underlying Lakehouse architecture.

- **Separation of responsibilities**

  Apache Spark and Spark SQL handle data processing, Trino provides analytical SQL access, and Apache Superset handles visualization.

- **Decoupling**

  The Business Intelligence layer does not depend directly on the processing engine. Trino acts as the SQL access layer between Apache Superset and the Lakehouse.

- **Governed consumption**

  Analytical users consume only Gold datasets, preventing direct access to raw or intermediate data layers.
